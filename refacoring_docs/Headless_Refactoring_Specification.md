## 1. 문서 목적

Chat On Steroids Headless 프로젝트의 리팩터링 요구사항을 정의하고, 기존 동작과의 호환성을 검토하며, 구현 및 검증의 기준을 기록한다.

**주의:** 본 문서는 리팩터링의 시작점인 초안이다. 목표 아키텍처, 삭제·교체 대상 및 최종 수용 기준은 아직 확정되지 않았다. 아래의 제안 항목은 승인된 구현 지시사항을 의미하지 않는다.

## 2. 프로젝트 현황 및 전제

프로젝트 README 기준으로 확인되는 주요 사용자 기능은 다음과 같다.

- 승인된 로컬 프로젝트 폴더의 파일 열람·수정 및 터미널 명령 실행
- MCP를 통한 로컬 Core 기능 연결 및 companion 브라우저 확장 연동
- 작업자(worker)를 통한 작업 분할 및 컨텍스트 재사용
- Goal/Loop, Compact & Resume 등 장기 작업 지원
- 권한·작업 폴더 설정, 모델 선택, 대화 및 도구 실행 결과 확인

README는 브라우저 UI 관찰·자동화, 로컬 대화 내용 기록 및 외부 서비스 정책 준수에 관한 제약도 명시한다. 리팩터링 시 이러한 특성을 변경 없이 유지할지 별도 결정해야 한다.

실제 모듈 경계, 호출 관계 및 테스트 커버리지는 코드 조사 후 보완한다.

## 3. 목표 및 비목표

### 3.1 잠정 목표 (승인 필요)

- 기능 변경과 내부 구조 개선을 분리하여 회귀 위험을 줄인다.
- 모듈별 책임, 인터페이스 및 의존성 방향을 명확히 한다.
- 작업 수명주기와 오류 처리를 추적 가능하게 만든다.
- 테스트 가능성, 로그 품질 및 유지보수성을 개선한다.
- 권한·보안·사용자 통제 체계를 훼손하지 않는다.

### 3.2 현재 범위 밖 (추후 변경 가능)

- 승인되지 않은 사용자 기능 삭제 또는 동작 변경
- 지원하지 않던 계정·서비스 우회 기능 추가
- 인증·권한 검사를 회피하는 자동화
- 근거 없이 정한 전면 재작성 또는 프레임워크 교체

## 6. 아키텍처 조사 체크리스트

코드 분석 후 다음 내용을 실제 파일 경로 및 호출 관계로 교체한다.

- [ ] 현재 런타임 엔트리포인트 및 프로세스 구성 파악
- [ ] Core / Desktop / companion extension / worker의 경계 확인
- [ ] MCP 도구의 스키마, 호출 경로 및 에러 포맷 조사
- [ ] 상태 저장 및 재개 데이터 형식 조사
- [ ] 권한 판정 위치와 실행 전 검증 로직 조사
- [ ] 설정 로딩 및 환경변수 우선순위 조사
- [ ] 중복 코드, 순환 의존, 테스트 공백 파악
- [ ] 기존 테스트·CI 및 배포 경로 확인

## 7. 리팩터링 진행 제안

| 단계 | 수행 내용 | 산출물 | 진입/종료 조건 |
| --- | --- | --- | --- |
| Phase 0 | 현재 동작 및 모듈 조사 | 모듈 지도, 인터페이스 목록, 기준선 | 실제 코드와 문서의 일치 확인 |
| Phase 1 | 대상·범위·호환성 계약 확정 | 승인된 요구사항, ADR | 기능 변경 여부에 대한 명시적 결정 |
| Phase 2 | 경계·계약 정비 | 소규모 변경 PR 및 계약 테스트 | 기존 기능 회귀 없음 |
| Phase 3 | 내부 구조 리팩터링 | 모듈별 변경 및 통합 테스트 | 기능·보안 기준 충족 |
| Phase 4 | 최종 검증 및 문서 정리 | 회귀 결과, 마이그레이션 안내 | 합의한 수용 기준 충족 |

이 단계 구분은 제안이며 일정이나 구현 착수를 확정하지 않는다.

## 8. 테스트 및 수용 기준

1. **동등성:** 승인된 변경을 제외하고 기존 사용자 동작이 유지되어야 한다.
2. **권한:** 승인되지 않은 경로·명령·도구 접근이 허용되지 않아야 한다.
3. **복구:** 중단·실패·재연결·재시작에서 상태가 일관되어야 한다.
4. **호환성:** 공개된 MCP 도구 계약과 기존 설정을 검증하고, 불가피한 변경은 문서화한다.
5. **성능:** 측정 가능한 기존 기준선과 리팩터링 결과를 비교한다.
6. **검증 증빙:** 테스트 실행 명령, 환경, 결과 및 남은 이슈를 PR에 첨부한다.
